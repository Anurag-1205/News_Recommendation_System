### What worked

- **Plan-mode before touching anything.** The plan was written and approved before any file was
  created. Two of the four blockers below were found *during* planning, i.e. before any code
  existed to throw away.
- **Probing rather than trusting the brief.** HTTP HEAD against every bundle URL produced real
  sizes instead of estimates.
- **The TA notebooks as a source for `SPEC.md` §6/§9.** Both submission formats and every row
  count came from the TA reference notebooks rather than from the model's
  memory — and are marked in `SPEC.md` as *not yet confirmed against the competition pages*,
  because second-hand is not verbatim.

### What failed — and how it was caught

1. **`articles_large_only.zip` 404s at the URL printed in `A1.pdf`.**
   The brief shows `…/artifacts/articles_large_only.zip`. That path returns **404**; the file is
   at the **bucket root**. Caught by HEAD-probing all seven URLs instead of assuming they were
   right — a line-wrap in the PDF had attached the `artifacts/` prefix to the wrong entry.
   Cost if uncaught: a failed download discovered on 25 Aug.

2. **The MIND dataset is gated; every download 401s.**
   The plan assumed `hf download` would just work. `GET /api/datasets/yjw1029/MIND` reports
   `gated: auto` and every `resolve/main/*.zip` returns 401. Caught by probing before writing
   the fetch logic. Requires a human to accept terms — no amount of retrying would have fixed it.

3. **The background downloads died three times, for three different reasons.**
   Each was caught by `ls -la` on the target directory rather than by trusting a
   "started successfully" message — the file size is the only honest progress report.
   1. *Launched via the agent's background-task mechanism.* The process exited with the
      session; both zips left truncated (`ebnerd_large.zip` at 6.2 MB of 2.97 GB). Relaunched
      under `nohup`.
   2. *`nohup` was not enough.* The fetchers still died. The logs gave two distinct causes —
      `Unable to establish SSL connection` on one, `Name or service not known` (DNS gone with
      the wifi) on the other. Both make `wget` exit non-zero, and under `set -euo pipefail`
      that killed the script mid-download. **`wget --tries=inf` does not help here**: it retries
      a stalled *transfer*, not a process that has already exited.
   3. *Fix:* an outer supervisor loop around each fetch that sleeps through the outage and
      resumes from the byte offset on disk, plus `setsid` for a genuinely detached session.
      The loop refuses to spin forever on `rc=8` (server error), so a wrong URL fails loudly
      instead of retrying a 404 five hundred times.

4. **The real blocker was the network, and the first measurement mis-attributed it.**
   Downloads were running at ~22 KB/s. The initial read was bandwidth contention between two
   concurrent fetchers. Testing a *single* stream against three independent endpoints — S3
   eu-west-1, Cloudflare's speed endpoint, HuggingFace — gave 13 KB/s, 4 KB/s and 101 B/s
   respectively, which rules out any one server. `ping 1.1.1.1` then showed **50% packet loss
   and 305–1225 ms RTT** on `wifi@iiith`. So: the link, not the source, and not contention.
   Consequence recorded in `SPEC.md` §11 — at 13 KB/s, `ebnerd_large.zip` alone needs ~63 hours
   of uninterrupted transfer, which does not fit before the deadline. Drove the recommendation
   to move the large-scale path to Colab/Kaggle.
   *Lesson:* the first plausible explanation for a performance number was wrong; the measurement
   that distinguished them was cheap — find the bottleneck by measurement, don't guess at it.

5. **`git init` had not actually run.** I believed the repo was initialised. There was no `.git`
   anywhere under `/home/anurag`. Caught by `git log` failing with "not a git repository" rather
   than by assuming the report was accurate.

  reference notebooks. Recorded in `SPEC.md` §7.
- **BM25 hand-written, `rank_bm25` as oracle only.** `SPEC.md` §10.3 — it is Module 2 material
  and exam-probed, so the library is the check, never the implementation.
